# 0.2.4 (2026-09-16) fixes the two root causes phase 4's Round 7 batch
# found together (see claude/smart-spatial-system-upstream-bugs.md Bugs 6
# and 7, and claude/phase-4-llm-arm.md Round 7/8):
#   - Bug 6: 0.2.3's own CRS-symmetry validator
#     (_validate_distance_op_crs_symmetry) falsely rejected every
#     correctly-chained multi-hop distance plan - exactly the shape this
#     repo's own accessibility query produces (sites -> +metro -> +schools
#     -> +parks). Fixed by walking back through a chain of distance
#     operations to find the originating crs_transform, instead of only
#     checking the immediate ref.
#   - Bug 7: a score_features factor missing "type" used to silently
#     default to "boolean" scoring - meaningless for a continuous distance
#     field, and not an error - collapsing every district's score to 0.0
#     with nothing in the pipeline raising. "type" is now REQUIRED (raises
#     both at generation time and at execution time, naming the field and
#     the valid types) rather than defaulting.
# Both fixes were verified directly against smart_spatial_system's own
# source (not just the CHANGELOG) on 2026-09-16, including a test added
# upstream that reproduces this repo's exact 4-layer/3-hop chain shape.
